# 문제 해결 기록

## Sanity CLI 인증

- `npx sanity documents query`는 로컬 CLI 로그인 세션이 없어 실행되지 않았다.
- 저장소의 기존 환경 설정과 `@sanity/client`를 사용해 토큰 값을 출력하지 않는 읽기/쓰기 스크립트로 대체했다.

## 네트워크 샌드박스

- 최초 Sanity 조회와 Kubernetes 조회는 샌드박스의 DNS/네트워크 제한으로 실패했다.
- 필요한 대상과 명령을 제한한 승인된 네트워크 실행으로 재시도해 해결했다.

## 브라우저 시각 검증

- Browser 스킬에 따라 연결을 초기화하고 사용 가능한 브라우저를 조회했으나 연결된 세션이 0개였다.
- 화면 자동화는 진행하지 못했고, 운영 HTML의 상세 커버 class, 이미지 URL, Open Graph 메타, 목록 분류, 상태 코드와 canonical을 직접 검사했다.

## SEO 기본 이미지 잔존

- 첫 운영 검증에서 실제 카드·상세 커버는 제거됐지만 이미지 없는 상세 페이지에 사이트 기본 Open Graph 이미지가 남아 있음을 발견했다.
- `SiteLayout`에 `null` 이미지 의미를 추가하고 콘텐츠 상세에서 `coverImage ?? null`을 전달해 사이트 기본 이미지 대체를 차단했다.

## 안전한 콘텐츠 이동

- 기존 회의 문서를 바로 제거하면 배포 전까지 이전 URL이 404가 될 수 있었다.
- 스터디 문서를 먼저 생성하고 301 리다이렉트를 배포·검증한 뒤 revision guard를 사용해 기존 회의 문서를 삭제했다.
