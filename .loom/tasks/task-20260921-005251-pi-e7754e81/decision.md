# 결정

## 독립 전사 흐름

- 블로그 구조화와 Sanity 발행 책임이 있는 `/meeting`을 확장하지 않고 `/transcribe`를 별도 extension으로 구성했다. 파일명 기반 전사 요청이 게시 흐름으로 번지지 않게 한다.
- 자연어 요청은 `transcribe_audio` tool 설명과 지침으로 연결하고, 반복 작업과 상태 확인에는 slash command를 제공했다.

## 정확도와 성능

- 기본값은 `accurate`로 정했다. 약 60초 최종 창마다 동일 구간 원본과 음질 보정본, 절반 길이 세부 후보 두 개, 앞뒤 30초 문맥 후보를 비교한다.
- 모든 후보 WAV를 한 폴더에 만들고 OpenSuperWhisper `bench` 한 번으로 처리한다. 후보별 모델 재로딩 비용을 피하면서 실제 CLI 계약을 따른다.
- 마지막에 지나치게 짧은 조각이 생기지 않도록 전체 길이를 `ceil(duration/target)`개 동일 구간으로 나눈다.
- Pi는 텍스트 후보만 받고 오디오를 받지 않는다. 대상 창의 시작·끝을 결과 JSON과 대조해 문맥 후보의 바깥 발화가 섞이는 것을 막는다.
- 속도가 필요한 경우에만 `fast`를 명시해 약 90초 원본 후보 하나를 사용한다.

## 파일 안전성

- 검색은 Unicode NFKC 비교를 사용하고 결과 파일명은 읽기 쉬운 NFC로 만든다.
- 동명 원본이 여러 개면 오류로 중단한다. 기존 결과도 `--replace`가 없으면 중단한다.
- 새 결과는 같은 디렉터리의 임시 파일에 완성한 뒤 하드 링크로 원자적으로 생성한다. 교체 승인이 있는 경우에만 rename으로 바꾼다.
- 원본 전체 SHA-256을 처리 전후 비교하고, run 산출물은 `.transcribe-agent/`에 두어 Git에서 제외한다.

## 개인정보와 재개

- 기본 검수는 후보 전사 텍스트를 현재 Pi 모델 제공자에게 보낸다. 이 경계를 문서에 명시했다.
- `--local-only`는 Pi 검수를 생략하고 로컬 원본 후보를 사용한다.
- `candidates.json`, 구간별 검수 JSON, 최종 `review.json`을 단계별로 재사용해 실패 후 음성 재전사와 완료된 Pi 구간 검수를 반복하지 않는다.
