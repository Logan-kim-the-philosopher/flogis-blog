# 결정 기록

## Pi의 책임 범위

- Pi는 회의 원본의 의미 해석, 주 분류 선택과 구조화 JSON 생성만 담당한다.
- `--no-tools`, `--no-session`, `--no-context-files`로 실행해 파일 수정이나 외부 쓰기를 할 수 없게 한다.
- 원본 보존, 오디오 변환·전사, schema 검증, person 연결, 중복 확인과 Sanity 쓰기는 결정론적인 Node 코드가 담당한다.

## preview와 publish 분리

- 원본에서 바로 운영 DB로 쓰는 단일 단계는 사용하지 않는다.
- `prepare`는 항상 로컬 preview만 생성한다.
- `publish`는 별도 명령이며 preview slug/document ID와 정확히 같은 `--confirm` 값을 요구한다.
- 기존 ID/slug 충돌 시 자동 update/upsert를 허용하지 않는다.
- 네트워크 쓰기 없이 운영 조건을 검사할 수 있도록 `--validate-only`를 제공한다.

## 분류 모델

- 독자가 기록에서 얻는 주된 결과를 기준으로 프로젝트 회의, 스터디·세션, 대화·인터뷰, 조직·팀 운영을 구분한다.
- 현재 Sanity 상위 타입을 늘리지 않고 스터디만 `study`, 나머지는 `meeting`으로 연결하며 세부 유형은 태그와 문서 기본 정보에 남긴다.
- 같은 날짜의 다른 회차나 다른 이름은 합치지 않는다.

## 정확성과 개인정보

- 사람·결정·기한을 추측하지 않고 불확실성 필드에 기록한다.
- 원본과 전사문은 Git에서 제외한 로컬 run 디렉터리에만 보존한다.
- 본문에서 제외한 잡담의 구체 내용은 공개 Markdown에 다시 싣지 않고, 건수만 표시하며 상세는 로컬 `structured.json`에 둔다.
- 썸네일은 자동 생성하거나 임의 연결하지 않는다.

## 전사기

- 로컬 설치 상태에 맞춰 `ffmpeg` + `whisper-cli`를 기본 adapter로 선택했다.
- 실제 한국어 회의에는 다국어 `large-v3-turbo`를 기본 설치 대상으로 사용하되, 사용자가 다른 ggml 모델 경로를 지정할 수 있게 한다.
- 모델은 약 1.6GB의 별도 런타임 자산이므로 저장소나 Docker 이미지에 포함하지 않는다.
