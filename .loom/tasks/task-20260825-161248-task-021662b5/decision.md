# 구현 결정

## 클로바는 API 연동 대신 전사본 입력으로 지원

클로바 계정/API 호출은 범위 밖이므로 TXT/JSON 내보내기를 입력받는다. 오디오와 함께 지정하면 오디오 원본과 메타데이터는 유지하면서 Whisper 비용을 제거한다.

## 날짜 근거의 우선순위를 명시적으로 고정

사용자 `--date`를 최우선으로 하고, 그다음 오디오 컨테이너 메타데이터, 마지막으로 회의 내용에서 Pi가 확정한 날짜를 쓴다. 파일 수정 시각은 복사·다운로드로 바뀔 수 있어 근거로 사용하지 않는다.

## 실패를 산출물 상태로 취급

전사와 구조화가 끝난 후 날짜만 없는 경우 전체 실행을 폐기하지 않고 `needs_input` manifest를 남긴다. `resume`은 기존 structured/post를 재사용하며 사용자가 편집한 본문을 덮어쓰지 않는다.

## 진행 상태는 파일 기반으로 전달

Pi의 `exec`가 자식 프로세스 출력을 완료 시점에 반환하므로 Node 오케스트레이터가 `progress.json`을 갱신하고 extension이 1초 간격으로 읽어 단계와 경과 시간을 표시한다. 이 방식은 Whisper 출력 형식에 의존하지 않는다.

## 발행 안전장치 유지

새 입력·복구 흐름은 preview까지만 자동화하고, 기존의 UI 편집·사전 검증·명시 승인 전 Sanity 쓰기 금지 규칙은 그대로 유지했다.
